## 2026-10-23：画笔/箭头无法删除或擦除（已完成，v0.3.7）

用户原话：画笔画出来的字没有删除也没有擦除，难道纯靠回档？

判据与实测：
- 笔迹点击命中带宽 ≥16px；选中检查器出现颜色/粗细/删除；真实鼠标改色和 6px 成功，`Delete` 后笔迹数 1→0。
- 橡皮擦 `E` 点击和拖过都能清理笔迹；两条笔迹拖过后 2→0；一次拖动只产生一个撤销快照。
- 截图中的蓝色箭头实际是连线（connector），不是笔迹；旧橡皮擦只认笔迹，所以擦不掉。现在连线命中带 12→16px，点击选中、`Delete`、右键“删除连线”、橡皮擦四种方式都通过。
- 回归：CDP 16/16 判据；Node 18/18；pytest 11/11；浏览器 smoke `ok:true`、`eraser:true`。
- 顺带修启动：pywebview 枚举 `FileApi` 公开属性时递归进入 Window 原生图，触发递归爆栈，API 注入被拖到 15 秒超时；非方法状态改私有后源码 smoke 秒过。之前的“启动不了/桥接未就绪”属于这一类间歇故障。

## 2026-10-23：APP 入口不稳定（已完成，v0.3.8）

用户反馈：Web 一直稳定，但 APP 打开始终成问题，怀疑前后端共用后端冲突。

根因与实测：
- Web 预览和 APP 不共用后端：Web 走 `BrowserBridge` + localStorage，APP 走 pywebview `FileApi` + `boards/`，只共用静态资源。
- 真正原因是单实例入口只看窗口标题：旧窗口的 WebView2 崩溃后变黑，但进程和 mutex 还在；之后每次双击只聚焦这个黑窗口，不会起新窗口。用“启动 → 杀 WebView2 → 再启动”稳定复现，黑窗口截图和旧 PID 都保留。
- 修复后：正常启动 5/5 约 0.7 秒出窗口；有标记和“无标记旧黑窗口”两种陈旧实例都被自动替换成新 PID/ready 窗口；最小化健康实例只恢复不误杀；快速双击仍只有一个窗口。
- 启动看门狗 25 秒兜底；日志写 `%APPDATA%/ThinkingCanvas/startup.log`。pytest 13/13、Node 18/18、源码/打包 smoke 通过。发布证据见 `实时进度.md`。
