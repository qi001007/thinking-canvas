# 前端设计规范

## 一、通用

1. **默认极简。** 新增任何 UI 前先问：没有它，用户还能完成这件事吗？能就删。
2. **常驻文案只写操作必需。** 解释、原因、教学、快捷键说明放帮助层或 `title`，不占版面。
3. **不重复。** 标题、标签、状态、toast 不重复同一信息；卡片内不写归属性说明。
4. **一个区域一个主动作。** 次要动作收进图标、右键或悬停，不铺一排按钮。
5. **提示一行。** 状态提示最多一行短句；toast 只用于失败和看不见结果的动作。
6. **留白优先。** 宁可少放，不把信息摊满；列表内部滚动，不撑高页面。
7. **短句、名词、数字。** 不用语气化文案，不在界面句末加句号。
8. **颜色/字号/间距用 token。** 不新起一套近似值。
9. **改了界面就截图。** 1:1 看清晰度，并检查窄窗口下是否拥挤。

## 二、文件 / 数据管理栏

10. **数据与管理独占一栏。** 画板、文件、数据列表不和数据无关的工具挤在同一列；列表再长也不得把工具区往下压。工具、编辑控件另起一栏。
11. **栏头固定。** 标题 + 数量 + 一个新建主动作；搜索框紧随栏头；列表在栏内滚动；目录、示例等辅助入口固定在栏底。
12. **每行自带身份。** 名称作主行，时间/类型等元数据作次行；当前项高亮；删除只在悬停或选中时出现。
13. **搜索即过滤。** 列表可能超过一屏就提供按名称搜索：`Ctrl+K` 聚焦、`Esc` 清空、`Enter` 打开首个结果；搜索时栏头显示“匹配/总数”，无结果只留一行空状态。
14. **边界可拖动。** 用分隔条调整栏宽并记住；每栏有可用的最小/最大宽度；双击分隔条复位。极端压缩收成图标轨道（图标 + 数量，点击恢复），极端展开不得挤垮画布；窄窗口按“画布优先”依次压缩。

## 三、状态与滚动条

15. **状态不常驻。** 启动或操作后短暂显示提示与计数，数秒后自动隐藏，并给一个关闭按钮；不为一行提示长期占用布局高度。
16. **滚动条隐式。** 细、圆角、统一 token 颜色；默认透明，鼠标进入对应栏或容器才显形；不得出现浏览器默认粗灰条，也不得常驻抢视觉。

项目内的说明性文案以本规范为准；算法/交互说明写在 `README` 或帮助弹窗里，不常驻画布。
