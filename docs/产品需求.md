# 产品需求：Thinking Canvas

## 一句话

一个本地 Windows 桌面画布，让用户在写代码之前，把函数的输入输出、数据结构、指针和每一步状态变化摆出来、看清楚。

## 目标用户

正在刷 LeetCode、准备面试或写算法函数的人。用户愿意在纸上推演，但希望少做重复劳动：不用每次都重画数组，不用自己找“这一步哪里变了”，不用擦掉上一步才能试下一步。

## 核心场景

1. 打开空白画布，放一个函数卡：函数名、输入参数、输出、复杂度目标。
2. 放数据：数组/矩阵、列表/栈、字典/集合、变量、节点（链表/树/图）。
3. 编辑当前状态：改格子、加/删行、移动指针、改字典项。
4. 点“记录一步”；继续修改；再记录。
5. 点时间线回看：历史只读，变化的格子/变量/指针自动标出。
6. 用便签写不变量、用箭头写关系；保存项目，下次接着想。

## 需求范围（v0.3）

- Windows 桌面应用；中文界面；默认 1450×900，最小 1100×700。
- 双栏管理：画板/文件管理独立成一栏，工具与数据控件另成一栏；列表再长也不挤压工具区。
- 画板栏：新建、切换、删除、搜索、打开文件夹、加载示例；按标题过滤，`Ctrl+K` 聚焦，`Esc` 清空，`Enter` 打开首个结果。
- 可拖动边界：画板栏、工具栏、检查器栏的宽度可拖；宽度持久化到 `boards/.ui-state.json`；双击分隔条复位；画板栏可压缩成图标轨道，工具栏可压缩成图标轨道。
- 所有画板 JSON 统一放在应用旁边的 `boards/`，删除移到 `boards/.trash/`。
- 无限画布：缩放、平移、框选、多选、拖拽、吸附参考线、撤销/重做。
- 数据卡片：数组/二维数组、列表（可当栈/队列）、字典、集合、变量、节点。
- 标注：便签、不变量、文字、函数卡、连线、矩形、画笔。
- 就地编辑：双击格子/值/标题/文字；数组支持区域选择、TSV 粘贴、批量输入。
- 步骤：记录当前快照；时间线前后翻看；步骤标题/备注；自动差异高亮；指针位置随步骤保存；步骤可从时间线或 Delete 键删除。
- 文件：当前画板自动保存到 `boards/`；新建/切换/删除画板；旧 `%APPDATA%` 会话自动迁移；窗口标题显示当前画板。
- 示例：一个可选打开的“冒泡排序 · 第一轮”画板，用于演示步骤/差异/指针；不自动加载。
- 错误处理：坏项目文件整体拒绝、保留当前画布；坏输入不写入项目。
- 状态提示：启动或操作后短暂显示，自动隐藏，也可手动关闭；不长期占用布局高度。
- 滚动条：细、圆角、统一颜色；默认透明，鼠标进入对应栏或容器才显形。

## 明确不做

- 不执行 Python/JavaScript 代码，不自动追踪局部变量，不读内存。
- 不预置算法模板中心，不替用户选择算法。
- 不自动布局树/图。
- 不做账号、云同步、多人协作、遥测。
- v0.1 不做分支时间线、伪代码行绑定、图片导出（进入路线图）。

## 验收标准

- 首次启动自动建一个空白画板；左侧画板栏能看到它，可新建、切换、删除、搜索。
- 画板栏与工具栏物理分栏；画板数量增加时工具区位置不变；三根分隔条均可拖动且记住宽度。
- 从“加数组 → 改值 → 加指针 → 记录两步 → 回看差异”形成连续可用流程。
- 历史步骤只读；回到当前可继续编辑；撤销/重做覆盖结构修改。
- 自动保存后重新打开，对象、布局、状态、步骤、指针位置一致；所有画板都在 `boards/`。
- 窗口版 exe 在 PATH 仅含 Windows 系统目录时能启动并通过 `--smoke`。
- 核心测试、画板/API 测试、真实 WebView2 smoke 全部通过。
- 界面文案遵守 `前端设计规范.md`：常驻说明文字只保留操作必需，教学与快捷键放帮助层；状态提示自动消失；滚动条隐式化。

## 方向演进

2026-10-22 早些时候曾把产品收窄为“空白格子纸 + 自由画板”，并明确不做步骤时间线。随后用户确认：需要的是“画布 + 手动推演 + 状态变化”，不是被具体算法示例绑死。因此当前版本恢复步骤/差异/指针作为核心，但仍然坚持默认空白、示例可选、不执行代码。详见 `反馈.md` 与 `决策.md`。
