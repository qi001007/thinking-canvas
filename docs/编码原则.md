# 编码原则

## 1. 分层边界

- `app/`：只做窗口、原生对话框、文件/会话 I/O；不掺画布逻辑。
- `web/js/core/`：纯数据与算法；不得访问 DOM、`window`、`localStorage`。
- `web/js/ui/`：渲染、事件、UI 状态；不复制核心数据，只读写项目对象。
- 打包脚本、开发服务器放 `scripts/`，不进入运行期。

## 2. 一个事实一个主人

- 项目结构、步骤、差异、指针位置只在 `core/` 定义。
- 数组卡片尺寸只在 `core/geometry.js` 定义；CSS 必须与它一致，改动两边一起改。
- 文件格式与校验只在 `core/model.js` / `core/serialize.js` 定义；Python 只做结构初检和原子写入。
- 文档里的命令和结论动手前对代码/测试复核；冲突以实现为准。

## 3. 交互优先于功能数量

- 常用操作不弹窗：就地编辑、浮层批量输入、检查器改属性。
- 每个操作有可见反馈：选中、hover、吸附线、toast、保存状态。
- 键盘可达：格子导航、Tab、Ctrl+Enter、Space 临时抓手、Esc 退出。
- 历史步骤只读；当前状态可编辑；不要用“看起来一样”的交互做危险操作。

## 4. 精准修改与可验证

- 每行改动能追溯到需求；顺手发现的缺陷登记到对应目录 `backlog.md`，不混进当前提交。
- 核心行为先写测试或至少写可复现步骤；UI 改动要真机截图，不只看 diff。
- 破坏性操作（删除对象、覆盖项目、强推）先确认；保存先写临时文件再原子替换。

## 5. 依赖与安全

- 运行期只依赖 Python 标准库 + pywebview；前端无第三方运行时依赖。
- 不执行用户代码，不联网，不收集遥测；项目数据只写本机。
- 所有用户文本进入 `innerHTML` 前必须 `escapeHtml` 或使用 `textContent`。
- 打开文件先完整验证；坏文件整体拒绝并保留原画布。

## 6. 项目卫生

- 每个 ≥2 个源码文件的目录放 `description.md`，改动追加到同目录 `backlog.md`。
- 构建产物、exe、缓存、归档不提交；发布走 Release。
- 中间截图/一次性脚本不进仓库；正式截图放 `screenshots/`。
